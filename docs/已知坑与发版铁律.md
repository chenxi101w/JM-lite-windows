# 已知坑与发版铁律（轻量版）

> 继承旧版 JMComicReader 的踩坑经验。改数据层 / 发版前必读。

## 一、发版铁律（数据安全）

1. **SQLite 表结构变更**：建表一律 `CREATE TABLE IF NOT EXISTS`；加列一律 `ALTER TABLE ... ADD COLUMN` 包在 `try/except` 里，**绝不** drop 重建清用户数据。
2. **配置默认值**：新增键进 `DEFAULT_CONFIGS`，写库用 `INSERT OR IGNORE` 保留用户现有值。
3. **破坏性操作必须先列清单确认**：删数据文件、清空表等一律先与用户确认。
4. **部署不碰 UserData**：`_build.py` 覆盖部署只覆盖 exe + appdata，跳过目标目录的 `UserData/`、`TempCache/`。
5. **打包前先关程序**：exe 被占用时部署会被跳过（WARN），zip 仍会生成。

## 二、已知坑（已踩过，勿重犯）

- **GBK 编码崩溃**：Windows 中文系统默认 GBK，jmcomic 打印含特殊字符（♡ 等）的标题时崩溃。`desktop_app.py` 启动时强制 UTF-8（`configure_utf8_output`），必须在 import 业务模块之前调用。
- **WebView2 缺失打不开**：需 Edge WebView2 运行时；开窗失败已做浏览器兜底。
- **端口固定**：`.app_url` 复用固定端口（28889），保证 localStorage / WebView2 存储不因端口变化丢失。**不要**与其他实例共用端口。
- **asyncio 下载**：jmcomic 的下载是异步的，下载服务需在独立线程跑 `asyncio.run`，不可直接在 Flask 请求线程里跑长任务。
- **exe 占用检测**：用 `open(path, 'r+b')` 抛 OSError 判断进程占用（不要用 tasklist 过滤，某些 shell 下会静默失效）。
- **启动类慢先埋点再动手**：不要凭经验猜瓶颈——v2.13.x 曾连猜 3 次全错（exe 解压 / 缺原生预窗 / Defender 白名单），最终埋点实测定位在端口探测。先出数据，再修。
- **端口探测用 bind 不用 connect_ex**：杀软（卡巴/火绒）会拦截本地回环**出站**连接（~1s/次），`connect_ex` 探测端口被拖慢成 ~2s；`socket.bind(("127.0.0.1", port))` 纯本地、零出站流量，杀软无感（v2.13.3 修复）。

## 三、构建环境

- 构建 venv：`.venv-build`（Python 3.11，基础解释器 `D:\code\app\Python311`）
- 依赖清单：`build/requirements.txt`
- 构建：`.venv-build\Scripts\python.exe build\_build.py`
